# 내 아이폰에서 채팅 수신 확인하기

목표: **안드로이드에서 보낸 채팅이 아이폰에 실시간으로 뜨는지** 확인한다.

---

## 먼저: 푸시(FCM/APNs)는 필요 없다

앱을 **켜서 그 채팅방을 보고 있는 동안**에는 메시지가 소켓으로 온다.
푸시는 앱이 꺼져 있거나 백그라운드일 때만 쓰인다.

| 상황 | 무엇이 배달하나 | 지금 되나 |
| --- | --- | --- |
| 앱을 켜고 그 채팅방을 보는 중 | **소켓** | **된다** ← 이번에 확인할 것 |
| 앱은 켜져 있지만 다른 화면 | SSE (인앱 토스트) | 아직 없음 |
| 앱이 백그라운드·종료 | APNs (FCM 경유) | 아직 없음. Apple Developer Program 필요 |

즉 이번 확인에는 **Apple Developer Program($99)도, FCM 설정도 필요 없다.**
무료 Apple ID 로 아이폰에 설치만 하면 된다.

---

## 1. 준비물

- Mac + Xcode, USB 케이블, 아이폰
- **백엔드 주소** (`Config/Local.xcconfig`)
- **앱 JWT** — 카카오 로그인이 아직 연결되지 않아 토큰을 직접 넣는다 (3번)
- 안드로이드 기기(또는 웹) — 보내는 쪽

## 2. 설치

```bash
git pull
./scripts/mac-setup.sh          # xcodegen generate 포함

cp Config/Local.example.xcconfig Config/Local.xcconfig
# API_BASE_URL 에 실제 백엔드 주소를 넣는다.
# xcconfig 에서 `//` 는 주석이라 `https:/$()/api.example.com` 처럼 써야 한다.
```

Xcode 에서 아이폰을 연결하고 `WeddingPlant` 스킴으로 Cmd+R.
서명은 Signing & Capabilities 에서 **본인 Apple ID 팀**을 고르면 된다(무료 계정 가능, 7일마다 재설치).

> 데모 스킴(`WeddingPlant (Demo)`)은 **가짜 데이터**라 백엔드에 붙지 않는다.
> 반드시 일반 스킴으로 실행할 것.

## 3. 아이폰에서 로그인 (임시 방법)

카카오 SDK 연동 전이라 앱 안에서 로그인이 안 된다. 웹에서 토큰을 꺼내 넣는다.

1. 브라우저에서 웹에 카카오 로그인
2. 개발자 도구 콘솔에서:
   ```js
   localStorage.getItem("plan_auth_token")
   ```
3. 나온 문자열(따옴표 제외)을 복사 → 아이폰으로 전달(에어드롭·메모 등)
4. 앱 첫 화면 아래 **"개발용 토큰으로 로그인"** → 붙여넣기 → 로그인

> 이 버튼은 `#if DEBUG` 로 감싸져 있어 **릴리스 빌드에는 없다.**
> 토큰은 계정 전체 권한이므로 남의 기기·공용 화면에서는 쓰지 말 것.

**안드로이드와 같은 계정으로 로그인하면 안 된다.** 서로 다른 계정이어야
"상대가 보낸 메시지"가 된다. 두 계정이 **같은 방(roomId)의 같은 채팅방**에 있어야 한다.

## 4. 확인

1. 아이폰: `참여 플랜` 탭 → 방 카드의 **채팅방 행** 탭
2. 화면이 뜨면 헤더 아래를 본다
   - 멤버 이름들(`지수, 현우`)이 보이면 **소켓 연결됨**
   - `연결 중...` 이 계속 떠 있으면 **아직 못 붙은 것** → 5번
3. 안드로이드에서 같은 채팅방에 메시지 전송
4. 아이폰에 즉시 말풍선이 뜨면 성공
5. 반대로 아이폰에서 보내 안드로이드에 뜨는 것도 확인

## 5. 안 될 때 — 로그부터 본다

소켓은 **조용히** 실패한다(자동 재연결이 계속 돌기 때문에 오류 배너를 띄우지 않는다).
Xcode 콘솔에서 `WPSocket` 으로 필터하면 프레임이 순서대로 보인다.

정상이면 이런 순서다:

```
연결 시도 wss://<호스트>/socket.io/?EIO=4&transport=websocket
← 0{"sid":"...","pingInterval":25000,...}     Engine.IO 핸드셰이크
→ 40/chat,{"token":"<가림>"}                   네임스페이스 접속
← 40/chat,{"sid":"..."}
네임스페이스 접속 완료, 방 입장
→ 42/chat,["joinRoom",{"room":10,"userId":"..."}]
← 42/chat,["message",{...}]                    ← 상대가 보낸 메시지
```

어디까지 갔는지로 원인이 갈린다:

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| `연결 시도` 후 아무것도 안 옴 | 주소가 틀렸거나 서버가 웹소켓을 안 받음 | `API_BASE_URL` 확인. `http://` 면 iOS 가 막는다 — `https` 필요 |
| `연결 끊김` 이 반복 | 서버가 `/socket.io` 가 아닌 경로에 붙어 있을 수 있음 | 서버 설정 확인 |
| `0{...}` 은 오는데 `40/chat` 응답이 없음 | 토큰이 거부됨 | 토큰 만료. 웹에서 다시 꺼내 온다 |
| `44/chat` 이 옴 | 서버가 접속을 거부 | 같이 온 메시지 확인 |
| 붙었는데 메시지가 안 옴 | 방 번호가 다름 | 두 기기가 **같은 채팅방**인지 확인 |
| 붙었다가 조금 뒤 끊김 | PONG 미응답 | 로그에 `→ 3` 이 보이는지 확인 |

메시지는 오는데 **화면에 안 그려지면** 페이로드 모양 문제일 수 있다.
`← 42/chat,["message",...]` 의 내용을 그대로 알려주면 파서를 맞춘다
(평평한 모양과 중첩된 모양 둘 다 받게 돼 있지만, 서버가 또 다른 모양일 수 있다).

## 다음 단계

이 확인이 끝나면 순서는 이렇다:

1. **카카오 로그인 실연동** — 토큰 붙여넣기를 없앤다
2. **인앱 알림(SSE)** — 다른 화면에 있을 때 토스트·미읽음 배지
3. **푸시(APNs, FCM 경유)** — Apple Developer Program 가입 후.
   백엔드가 지금 `data` 만 보내는데, iOS 는 그것만으로는 배너가 뜨지 않는다.
   iOS 대상에는 `notification`(또는 `apns.payload.aps.alert`)이 함께 필요하다.
